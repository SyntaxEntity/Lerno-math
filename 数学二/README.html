考研数学二 · 速成复习资料

面向已经系统学过数学二、需要快速过一遍的考生。每章固定六段式： 考频统计 → 核心讲解 → 关键结论速记 → 示意图 → 易错点 → 真题示例。 本资料由脚本生成（数学二/scripts/），不要手工编辑 数学二/ 下的 .md。

一、考试结构（已核实）

单项选择题 10 题 × 5 分 = 50 分

⚠️ 试卷结构沿革（这条很重要，能解释市面上互相矛盾的说法）

网上流传的两套「题型分值」说法都曾经是对的，因为它们对应不同年份：

时期 单选 填空 解答 合计
2020 年及以前 8 题 × 4 分 = 32 分 6 题 × 4 分 = 24 分 9 题 = 94 分 150 分
2021 年起（现行） 10 题 × 5 分 = 50 分 6 题 × 5 分 = 30 分 6 题 = 70 分 150 分

核实方式：直接读真题原件的卷首说明（本地真题语料，见第六节）：

  • 2020 年数二：「一、选择题(1～8 小题，每小题 4 分，共 32 分)」
  • 2022 年数二：「一、选择题（1~10 小题，每小题 5 分，共 50 分）」 「二、填空题（11~16 小题，每小题 5 分，共 30 分）」「三、解答题（17~22 小题，共 70 分）」
  • 2023 年数二：同 2022
  • 2024 年数二：选择题 1～10（每题 5 分，共 50 分）；解答题 17～22

备考一律以现行结构（2021 年起）为准。 本资料的题型标注均按现行结构。

范围边界（据数二考试大纲）

  • 考：函数、极限与连续；一元函数微分学；一元函数积分学（含反常积分）； 多元函数微积分学（含二重积分）；常微分方程；线性代数六章。
  • 不考：概率论与数理统计；无穷级数；向量代数与空间解析几何； 三重积分、曲线积分与曲面积分；线性代数中的向量空间（数一内容）。

一处需要你确认的差异：任务书中原本把「多元函数微积分学」列为不考。 但核实大纲与真题后发现它是要考的：2025 年数二大纲原文列有 「四、多元函数微积分学」（二元函数极限与连续、偏导数与全微分、多元复合与 隐函数求导、多元极值与条件极值、二重积分）；真题层面，2024 年第 5、6、12、20 题、 2023 年第 13 题、2022 年第 2 题均涉及多元函数或二重积分。 因此本资料按大纲增列了「09-多元函数微积分学」一章（高等数学共 9 章）。

核心讲解的阅读结构：每章的核心讲解都按「【模块名】+【核心公式】+【适用条件】+【易错提醒】」 组织，用 ## 分模块、列表拆解、公式单独成行、易混淆内容用表格对比 （如反常积分两类、微分方程特征根三种情形），关键条件加粗显示。 在 HTML 里这些模块会渲染成 h3/h4 层级，可直接用浏览器的文档大纲跳转。

Markdown 的定位：数学二/**/*.md 是由 parts/ 生成的中间产物， 用途是版本管理与二次加工，阅读体验不如 HTML。二者都由脚本生成， 改内容请改 parts/ 后重跑 run_all.py。

3.2 「考察次数」的口径与已知局限

  • 样本：2023—2024 年数二真题逐题定章统计，共 2 套（44 道题）。 样本量小，请勿把「次数」当作长期占比来用——它的用途是区分「必考主线」 与「偶发考点」，而不是精确估计分值。
  • 计数单位：一题计 1 次；解答题串联多个考点时，计入其主要考查的那一章。
  • 为什么只用这两年：2021 年才改为现行结构；且本地语料中 2021、2022 两年的 OCR 文本存在题面缺失或答案与题干交错，无法逐题定章。把抽不到的年份算作 「没考」会系统性低估，因此不计入。
  • 不确定度：定章依「主要考查内容」判断，边界题（如「变限积分 + 极限」） 可能归入相邻章节，存在 ±1 次的不确定度。
  • 「考频待补充」：官方从不公布逐知识点考频，任何具体次数都来自第三方统计、 口径不一。凡本资料无法核实的条目一律标注考频待补充，绝不编造次数。

3.3 与市面考频表的预期差异

市面辅导书（李永乐 / 张宇 / 武忠祥系列）公布的考频表多覆盖 10—15 年，且统计口径 （按题次 / 按分值 / 按知识点拆分粒度）各不相同，与本资料的两年样本不可直接比较。 本资料的做法是：只给能自证的数字，其余标注待补充，并在正文里给出该章的实际 命题方式（题型、常见考法），供你按题型判断优先级。

五、图形与数值的可验证性

  • 图形一律「先代码后图形」：所有精确图像由 数学二/scripts/figs/*.py 用 matplotlib 生成到 数学二/assets/，正文以相对路径引用。 不手写 SVG，不用 ASCII 硬凑函数图像。
  • 数值一律 sympy 复算：数学二/scripts/verify_math.py 会复算资料中出现的 极限值、导数、积分、反常积分敛散性、微分方程通解/特解、行列式值、秩、逆矩阵、 方程组的解、特征值与特征向量、二次型标准形与正定性，以及几何应用中的 面积、体积、弧长。
  • 图上标注的关键点坐标必须等于 sympy 算出的值：这是硬性要求， verify_math.py 会断言失败即报错。
  • mermaid 图用官方解析器真实 parse()：静态正则查不出「标签含圆括号未加 引号」这类直接解析失败的写法，所以校验器调用 数学二/scripts/check_mermaid.mjs（node + 官方 mermaid）逐图真解析； 扫描根跟着模式走——--parts 扫内容源 parts/，成品模式扫 数学二/， 这样在「改 parts → validate.py --parts」的内层循环里也能立刻看到写坏的图。 解析器不在、node 不在、返回码非 0、一块图都没扫到——这四种情况都会让校验 直接失败，而不是打一句「跳过真实解析」然后照样全绿。确实要离线跳过时， 必须显式写 python3 数学二/scripts/validate.py --no-mermaid。

七、工具链用法

7.1 依赖（两条命令即可重建出逐字节一致的运行时）

本项目自带站内运行时，生成站点时必须拿到完全相同版本的组件，否则校验的语法 与线上渲染的不是同一个版本：

# Python 侧（绘图 + 符号复算 + Markdown 渲染）—— 版本锁在 requirements.txt
python3 -m venv .tools/venv
.tools/venv/bin/python -m pip install -r 数学二/scripts/requirements.txt

# Node 侧（mermaid 真实解析校验 + 站点内置运行时）—— 版本锁在 tools-package.json
# 先把清单拷进 .tools/ 再让 npm 按清单装：与 CI（.github/workflows/pages.yml）
# 走的是同一条路径，因此本地和线上不可能装出两个版本。
mkdir -p .tools && cp 数学二/scripts/tools-package.json .tools/package.json
npm install --prefix .tools --cache /tmp/npm-cache --no-audit --no-fund

这里不再写版本号：版本只在 requirements.txt 与 tools-package.json 里各写一次， 工作流、校验器与本文档都从这两个文件读（PLAN-对齐与改版 §1.2 的单一数据源要求）。 下面这张表由构建时读取那两个文件生成，因此永远不会和实际依赖跑偏。

组件 锁定版本 来源文件 用途
jsdom 30.1.2 tools-package.json 给 mermaid 的 parse() 提供最小 DOM
katex 0.16.47 tools-package.json 站点内置公式运行时（含 60 个字体）
mermaid 12.1.0 tools-package.json 站点内置图运行时 + F3 真实解析校验
sympy 1.14.0 requirements.txt 全部数值复算（含图上坐标）
matplotlib 3.11.2 requirements.txt 生成 assets/*.png
Markdown 3.11.1 requirements.txt Markdown → HTML

为什么要锁版本：站点里内置的 mermaid.min.js / katex/ 就是上面这两个版本， 而 F3 用同一个 mermaid 做解析校验——版本漂移会造出「校验过了但页面渲染不出来」 这种最难查的情况。run_all.py 开跑前会比对实际安装版本，不一致直接报出来。

.tools/ 是 gitignore 的本地依赖目录，可以随时删掉重建； check_mermaid.mjs 则放在受版本管理的 数学二/scripts/ 下—— 校验逻辑必须进仓库，否则「删掉 node_modules」就等于悄悄关掉了 F3。

python3 数学二/scripts/run_all.py

# 或分步执行
python3 数学二/scripts/verify_math.py            # sympy 复算全部数值 + 图文一致性

python3 数学二/scripts/build_html.py             # 生成 HTML 站点
node 数学二/scripts/check_mermaid.mjs --strict   # 单独跑 mermaid 真实解析

# 打包成待发布的站点目录（仓库内，已 gitignore；注意会先清空输出目录）
python3 数学二/scripts/pack_site.py math2-site

站点不入库、由 CI 现打包：仓库跟踪的是源码、内容源、生成物与工具链； math2-site/ 是 pack_site.py 的产物，随 .gitignore 排除。 发布走 .github/workflows/pages.yml：推 main → 装依赖 → validate.py 门禁 → pack_site.py math2-site → 上传 artifact。所以本地要看站点，自己跑一次打包即可 （或直接打开 数学二/index.html，那同样是离线可用的站点）。

run_all.py 会自动挑一个同时具备 sympy / matplotlib / markdown 的解释器 （优先用 .tools/venv/），并把 MPLCONFIGDIR 指到 .tools/mplcache ——本机 $HOME/.config 是只读的，不设它每次都会退到随机临时目录重建字体缓存。 Node 依赖缺失时它会在开跑前明确报出来，而不是等 F3 静默跳过。

八、我无法自验的部分（请你确认）

  1. HTML 中的 mermaid 渲染效果：本环境无浏览器。我能验证的是—— 15 块 mermaid 源码全部通过了官方解析器的 parse()（解析器版本与站内运行时 同源，见 7.1 的依赖表与 tools-package.json）、容器数量、脚本可达、锚点齐全、 无绝对路径。 实际渲染出的图形请你在浏览器里打开 数学二/index.html 看一眼。 若解析器或 node 依赖缺失，校验会直接失败并告诉你装什么，不会静默跳过。
  2. 考频次数的绝对值：见第三节，只有 2023—2024 两年样本，存在 ±1 次不确定度。 若你手上有更完整的考频表，改 数学二/scripts/meta.py 一个文件后重跑 build.py 即可全局同步，无需改正文。
  3. 真题题面的 OCR 准确性：语料来自第三方 OCR。标注为「原题」的题目我已逐字 比对语料，但若语料本身识别有误，题面可能仍有偏差。建议你对照纸质真题复核 第六节 6.3 的清单。
  4. 数学结论的表述风格：定义、定理条件已按同济《高等数学》《线性代数》口径 撰写并做条件完整性检查，但「是否讲得够清楚」需你按自身基础判断。
  5. 考频次数的代表性：样本只有 2 套（共 44 题）。 「考察次数 7 次」这类数字是该样本内的计数，不是长期占比。 若你手上有更完整的考频表，只需改 数学二/scripts/meta.py 一处， 重跑 run_all.py 即可让正文、总表、HTML 三处同步更新。
  6. HTML 的公式与图形渲染效果：公式用打包在本地的 KaTeX（数学二/katex/， 含 60 个字体文件）在浏览器端渲染，mermaid 用本地 mermaid.min.js 渲染，均离线可用。 我能验证的是：文件已复制、<script>/<link> 引用可达、mermaid 源码能被官方解析器 parse() 通过、页面无绝对路径——但本环境没有浏览器，无法替你确认最终排版观感。 请打开 数学二/index.html 看一眼公式与图；若某处渲染异常，页面会显示明确的 「未加载到公式渲染器 / 该图渲染失败」提示，而不会静默留白。
